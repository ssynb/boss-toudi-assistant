# 核心修改索引

- 改 HTTP/UI 接口：先改 `contracts.ts`，通知 UI 维护者；路由在 `server.ts`，禁止增加平行接口说明文件。
- 改审批、恢复、去重：读 `state.ts` 与 `executor.ts`。SQLite 写前记账是发送的授权边界，模型线程恢复不能代替它。
- 改模型工具：读 `codex.ts`、`advisor.ts`、`search-plan.ts` 与 `discovery.ts`。动作原文只能来自最新用户消息的开始意图；筛选条件可沿用最近任务和明确用户历史，额度来自联系账本；模型回合正常结束才启动任务。线程 ID 校验与整次工具串行队列不可移到提示词；Codex 版本升级要重跑越权测试。
- 改站点交互：读 `boss.ts`、`boss-chat.ts`、`browser.ts`、`browser-responses.ts`、`cloak.ts`、`command.ts`。历史完成以绑定当前会话的成功响应为准，DOM 只核对当前身份与新到消息；观察失效不能沿用旧的零消息证明。Cloak 官方 wrapper 在隔离环境里运行，不加载个人 key、不回退普通 Chrome。真实核验范围与未验边界见 `../docs/architecture.md`。
- 改输入保存：`resume.ts` 只做校验/解码，`state.ts` 把原始字节与输入/批准变更同事务落库；不能恢复分散上传或确认入口。本地文件不是 BOSS 站点附件。
- 改发现计时：SQLite 是状态与时间的唯一来源，stopping 不等于已经结束；在途工具结束前不能填写 finishedAt。

- 改调研或求职对话：读 `research.ts`、`advisor.ts`、`model-task.ts`；方向逐项保存，模型只提交结果。任务互斥覆盖认证预检查，停止等在途读取结束；持久化与中断恢复归 `state.ts`。

- 改发现/执行衔接：找到就投逐JD判定后执行，首目标创建运行批次、后续原子追加并批准新版本；单目标与整批必须共用Executor安全步骤。只找不投在验证、用户停止或站点异常后保存已确认入选草稿，模型判定失败不保存。找到就投仍暂停并保留已执行事实，不额外发送。
- 改方向预算或筛选报告：每方向先保留count×6份读取预算，余量只向后顺延；配额按入选计，执行结果另计。拒绝只持久化类别计数，不保存理由全文。

- 改薪资筛选：`search-plan.ts`统一校验salaryMinK上限口径并解析卡片薪资；明确不满足才跳过JD，面议等未知继续读取。预筛计入薪资不足并单列，不消耗方向详情预算。

- 改发现读取节奏：范围以`discovery.ts`的READ_PACING_MS为准，等待支持取消；验收经AppOptions注入ReadClock，不通过环境变量跳过生产等待。

- 改浏览上限：计数由站点实际导航前的beforeJobOpen回调触发，复用不计；State按北京时间日持久计数，不能按jobDetail/openJob调用次数猜导航。
- 改招呼与筛选：固定招呼只从统一保存入口写入，判定工具不生成文本；只按硬条件和方向大类筛选，用户明确额外限制才可拒绝，须核对原文。
