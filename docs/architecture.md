# 后端结构与验收边界

## 进程与数据流

一套 Node 本地 HTTP 服务负责状态和编排，静态 UI 放在 `public/`。Codex app-server、agent-browser 及 CloakBrowser 是受控子进程，不存在 Python、容器或远程控制平面。TypeScript 直接由 Node 执行；最低版本 24.11.0 已在 macOS 实测可用原生 TS 与 node:sqlite（该版本 sqlite 仍会输出实验警告）。

对话是调研与新投递的唯一入口。个人信息页保存简历和可选求职偏好，具体方向、数量与是否立即发送由最新用户消息决定。顾问回合只开放 reply、start_research、start_delivery、send_saved_batch；动作 quote 必须逐字包含于最新用户消息，证明这次开始意图；不能引用旧对话授权。城市、薪资、方向和筛选条件可沿用最近任务计划及对话中用户明确的条件，最新修改优先；不要求用户在“继续”“再投147个”时重述全部条件。程序复述本轮条件，并继续校验城市、方向配额和当日剩余额度。工具拒绝后模型可回复说明；工具接受仅暂存动作，回合失败或取消不启动任务。用户已选择一句话直接开始，不再弹确认卡。旧的独立开始发现/调研接口已移除，停止接口保留。

发现流程：已授权对话计划 → 程序按方向配额搜索、连续翻页、去重并读取实际 JD → 独立小批判定 → 累积草案。每个方向达到自己的 count 即转下一方向，不用一个方向的多余结果抵另一方向的配额；同一岗位不能重复入选，实际 JD 可跨方向复用但重新按该方向判断。判定上下文以本轮 criteria、城市、薪资和方向为准，已保存偏好仅作背景。每批最多10个JD，判定失败最多重试本批一次；整轮详情读取预算为总目标数×6。搜索范围或预算耗尽时正常保存已入选结果并说明不足。浏览器单页搜索或单JD读取异常重试一次，仍失败则跳过并报告搜索/详情失败计数；重试不重复占用同一JD的读取预算。同一关键词连续3页失败，或全局连续5个读取单项在重试后仍失败，判为站点异常提前结束：已正常入选的目标保存为新草稿，但结果类型为partial，禁止自动发送，用户可另说“投吧”。没有新入选则保留旧批次，不提示发送旧批次。成功读取会清除全局连续失败计数；成功搜索页会清除该关键词的连续失败页数。SiteBlockedError、用户取消和模型判定失败不走此容错分支，仍不替换旧批次、不自动发送。方向目标数与入选数写入 SQLite，开始、方向完成及最终结果作为简短 assistant 消息写回对话，不贴招呼原文。搜索仅涵盖计划关键词与站点允许的加载范围，不代表全站耗尽。

执行流程沿用批准当前批次版本 → 确定性执行器 → 浏览器适配器。sendNow=true 时，在发现正常完成且有入选后同步批准刚生成的版本并执行；false 只存草稿，后续对话「投吧」通过 send_saved_batch 启动保存的批次。投递记录中的恢复/继续接口仍校验当前版本。执行器的身份、防重、未知不重试、不发附件和暂停规则不变。批次版本跨批次单调递增，旧批准不能授权新目标。

contactedToday 直接由 contacts.at 按本地自然日的起止时间统计，不使用UTC日界线；已联系、跳过或未确认记录都计入。新投递总量不能超过单批上限和每日剩余，保存批次开始执行前也重新检查潜在新增联系数。页面仅展示此统计，不能另维护一套额度。

调研流程：模型根据简历与偏好提出5–10个相关方向 → 程序在本轮指定城市按方向搜索 → 每方向至多读取合同规定的详情数量 → 独立回合评估匹配程度、理由、短板和匹配数。已联系岗位和方向内重复岗位不采样，空 JD 不作有效样本；无样本明确说明无法评估。薪资由程序汇总有效样本岗位卡，可识别的月薪K合并区间，其他格式保留原文。每完成一个方向即保存、排序并通知 SSE；停止或失败保留已完成方向。

顾问上下文包含简历、偏好、调研结果、投递概况、最近对话和SQLite中的最近任务摘要。摘要保存任务类型、完整计划、结果/失败原因、入选及送达数，重启不丢失；它是内部上下文，不新增HTTP配置入口或授权入口。显式的猎头/中介/外包排除及解除排除按用户表述保留到criteria，不能从岗位页面推导条件；判定提示要求按criteria拒绝猎头代招、人力中介和相应外包岗位。概况区分全局账本数量、今日联系数、当前批次各步骤计数；送达公司名单只来自当前批次招呼 done，可截断且标明范围，未知不能当作零记录。HTTP 接受消息后返回 pending，后台模型正常结束才接受回复或动作；失败写入可读消息并复位。历史在 SQLite 按合同限长限条数，clear 同步清空。没有定时投递任务。

对话与其启动的任务共用一个生命周期，认证预检查也占用任务，防止抢用 Codex；调研、发现、批次执行和新的对话互斥。任务进行中不能改资料、改稿、清空对话或导航浏览器。停止先进入 stopping，等在途读取结束后记终态；任务终态与互斥释放在同步段内完成。中断恢复保留已完成调研、方向进度和账本，未确认发送不重试；持久化失败明确报错，不宣称成功。

## 职责

- `app.ts`：生命周期、互斥编排、事件通知。
- `state.ts`：具体要求、简历原始字节/正文与批准失效同事务保存；发现与调研状态/时间、对话历史、批次版本、跨批次联系账本与崩溃恢复。
- `executor.ts`：逐步骤执行与暂停，任何对外动作前先记录 inflight。
- `codex.ts` / `discovery.ts` / `search-plan.ts`：stdio RPC、登录、拒绝越权审批、根线程工具权限、对话动作校验、按方向配额发现与独立JD判定。
- `research.ts`：方向建议、确定性只读抽样、独立方向评估与岗位卡薪资统计。
- `advisor.ts` / `model-task.ts`：对话上下文与受限任务选择；工具接收不等于模型回合成功，回合完成前不执行任务。
- `browser.ts` / `boss.ts`：agent-browser 遥控 CloakBrowser、岗位读取、联系前重新观察及身份复核。
- `boss-chat.ts`：所有联系后的去向与重启恢复汇合到已有会话读取；负责连续历史证明、当前会话核对、输入准备和提交前防重。
- `browser-responses.ts`：按当前标签页订阅特定接口的网络事件，只读开启观察后发起并完成的响应；不主动请求接口、不保存 URL 或正文、不向模型开放 CDP。关闭、断连、超时、溢出均明确终止观察并释放连接，不能把读取失败变成空结果。
- `cloak.ts` / `cloak-runtime.ts`：隔离调用官方 wrapper、检查已有免费版、用户确认许可后的官方下载；不读取个人 key、不回退其他浏览器。
- `resume.ts`：有上限的严格 base64 解码、文件格式校验与文本提取，不写磁盘；字节交给 SQLite。pdf/docx 不解析，因此不需要 PDF/ZIP/Office 解析依赖。
- `server.ts`：HTTP、SSE、静态托管和本机来源校验。

接口形状、错误与语义只维护于 `src/contracts.ts`。

## 统一保存与计时

只提供一个输入保存入口。选择文件只是 UI 草稿；服务端先校验完整请求，再把文件字节、元数据、正文、具体要求与旧批准失效放进同一 SQLite 事务。没有跨文件/数据库的双提交，更新或删除失败都会回滚。旧版磁盘简历迁移时先读文件并核对哈希，事务保存原始字节与清理标记；提交后才删原文件，清理失败中止启动并保留标记供重启恢复。

发现状态与 startedAt/finishedAt 的唯一来源是 SQLite。认证/输入预检查失败不重置上轮时间；接受开始后记录 startedAt；停止请求只转 stopping，等待 Codex 回合及在途只读工具结束后才固定 finishedAt。成功、停止和错误均有终态；进程意外中断在重启恢复时记录中断原因及检测时间，不伪造实际崩溃时刻。事件推送通知状态变化，后端不轮询计时。

App 的取消令牌同时保护开始前的异步认证检查；保存同步进入数据库事务，完整工具操作仍串行。发现期间与停止过程中禁止保存、改稿或执行批次。

## 本机隔离

数据目录下：`state.sqlite` 存业务事实与简历原始字节（BLOB）；`cloak-profile/` 存专属 CloakBrowser profile（不使用旧普通浏览器 profile）；`codex-home/` 由 Codex 自行存登录；`codex-user-home/` 隔离用户技能；`codex-work/` 是独立工作目录。

Codex 不复用用户其他客户端的目录，避免继承 MCP server、hooks 与 AGENTS。子进程不继承 API key、NODE_OPTIONS 等隐式配置。agent-browser 使用项目显式配置而非用户默认配置，不启用插件。浏览器二进制只能来自 Cloak 官方缓存，启动总是显式传 executable-path 和官方指纹参数；profile seed 持久化。Cloak wrapper 子进程剥离外部覆盖、key 和下载源变量，使用应用专用缓存/HOME；共享旧缓存仅取指定免费版文件。Unix socket 使用短的隔离临时路径，不触碰 bbu 的会话。模型 shell 与浏览器工具关闭；文件修改、命令和权限审批均拒绝。

HTTP 只接受实际监听端口对应的回环 Host；有 Origin 时必须同源，跨站 Fetch Metadata 被拒；所有 API 包括读取和事件流均要求专用头，无 CORS。CSP 禁止内联脚本和外部脚本，允许内联样式；设计师应把 JS 写到 `public/` 的独立模块。

## 真实站点限制

真实登录态核验已覆盖岗位页身份、已有会话读取与搜索滚动分页。在用户授权的50岗批次中，48条批准招呼取得送达/已读证据；1项没有沟通入口，1项与已送达目标为同一招聘者，经只读核对后排除。旧未知记录没有重试，没有发送附件。此批次结果不证明所有页面形态均可用。

- 岗位页从沟通入口的站内聊天地址读取岗位 ID 和招聘者 ID，多个入口须一致且岗位 ID 与目标 URL 相符。招聘者 ID 是不透明值，URL 解码后按原值精确比较（包括 `~`），不靠本地字符白名单判断身份；不向模型、日志或账本传递地址中的安全参数，不主动请求添加联系人接口。
- 立即沟通仍视为可能触发默认招呼的对外动作，必须获批后执行；动作前重新定位并核对身份，不复用旧引用。联系后的路由、弹层、新标签页都进入同一流程：打开通用聊天页 → 开始被动观察历史响应 → 选择岗位与招聘者均匹配的唯一已有会话。
- 「继续沟通」只说明已有会话，不再点击该入口；只读核对历史后，已有本方消息则跳过，完整证明零本方消息才可在批准后发送招呼。全局账本中的已联系和结果未知目标在此之前直接跳过，不能通过已有空会话重新授权。
- 当前会话同时核对所选会话、顶部详情和消息区域绑定的岗位/招聘者 ID，并核对公司，避免切换过程中读到上一会话。身份来自页面组件的已加载数据；字段缺失就停止，不能以姓名或公司名代替身份。
- ID 身份与联系完成状态同事务保存。旧 URL 身份保留其原有严格核对路径，不猜测转换为 ID；缺失身份的旧记录仍要求用户手动核对，不重复联系。
- 历史完成事实只来自观察开启后的成功响应：HTTP 200、业务码 0、消息数组与明确结束标记，且请求招聘者、页码/游标及消息双方归属可核实。见到本方消息即可判定不能重复发；只有连续读到结束才可判零，读取失败或超时不是空历史。
- 页面身份与历史证明分工明确：DOM 核对当前岗位、招聘者、账号及历史后新到的消息，不用 Vue 加载零值或页面高度推断历史完整。证明须绑定本次观察，重新请求、导航、切换会话或观察失效后不能沿用旧的零消息结论。
- 填写前、提交前各核对本方消息；出现自动招呼就跳过本次发送，账本记为 skipped 而非 done。填写后确认原文逐字一致、输入区已稳定且发送控件可用，不能把填入等同发送。
- 不发附件简历：BOSS 要双方沟通后才能发附件，由用户本人在站点完成。
- 用户关掉浏览器窗口后，agent-browser 的下一条命令会自建空白页。状态检查看到空白页就关闭浏览器并报告「已关闭」；发现时搜索会重新打开浏览器。已登录账号访问登录页会在加载后跳回首页，所以「BOSS 登录」先打开首页，只有未登录才进登录页。
- 岗位卡薪资用站点私有字体显示数字（U+E031–U+E03A 对应 0–9），提取时还原；站点换字体映射会让薪资显示错误。
- 发送确认要求目标会话中新增的本方消息与批准原文一致，并显示送达或已读；乐观回显、发送中、失败提示都不是成功。没有确认就记录 unknown，浏览器命令中途抛错同样不能当作未发送。

## 验证

`npm run check` 包含规则、HTTP、真实 Codex 进程连接假模型、真实 CloakBrowser 本地快照/填入/点击。Windows CI 与 macOS CI 运行完整测试，而非仅类型检查。macOS 与 Windows x64 的 Node 24.11.0 / 24 LTS CI 已通过；CI 下载前需要仓库所有者确认许可并设置对应变量。Windows 原生 arm64 不受当前 Cloak wrapper 支持，直接报错。

既有会话及新建会话后的真实招呼发送已在授权批次验证，原文及岗位/招聘者匹配保持核对。真正零记录和多页历史的专门真实响应样本尚未留证，本地合成站点覆盖不代替这些取证。跨岗位同招聘者可能因已有会话绑定另一个岗位而暂停，本次通过只读核对已发送身份后排除了重复项，不能靠放松岗位匹配继续发送。后续操作须遵守用户指定目标和次数，不自动扩大批次；未跑满真实账号的百岗位投递，不保证每轮达到目标数。
